# Security

The supported milestone is a read-only prototype with automatic local Codex inspection. It supports observed cleanup previews and locked confirmation, not real Codex deletion. Missing metadata is uncertainty, not evidence that a record is orphaned or disposable.

Do not upload private transcripts or credentials in public issues. Prefer GitHub's private vulnerability reporting if enabled, or contact the maintainer through GitHub for a private channel.

The app starts by inspecting real local data. The native IPC and loopback-only development browser adapter parses bounded Codex session headers, title index and desktop pinned IDs; other files are stat-only. Metadata and keep choices remain in memory. There is no backend account, telemetry, SQL connection, agent subprocess, custom root chooser or automatic cleanup. Real records are always protected and have no export API. Cleanup analysis is observation only. The native cleanup request handler unconditionally returns realStoreLocked before source or process access; no environment, renderer payload, sourceKind flag or configuration can unlock it. Symlinks are not followed. External database roots, remote data, runtime activity and compressed session contents are excluded. OS read access times and concurrent Codex writes are not an atomic immutability claim. Security boundaries are covered by the test plan; a successful build does not prove future destructive operations safe.

The localhost development endpoint only accepts GET requests from a loopback socket with an allowed Host, matching Origin/fetch metadata and application request header. It emits no CORS permission or cacheable metadata, accepts no source-root input, uses a fixed own-project CLI command with no shell, and does not log inventory contents. This is a local-owner boundary, not isolation from a malicious process already running as the same OS user.

## Synthetic cleanup isolation

The default feature set excludes `synthetic_cleanup`. The explicit developer feature creates a new private TempDir with fixed generated basenames under data/ and receipts/ inside the same tree. It accepts no existing root, real inventory or CODEX_HOME input. Private stored plans use the shared scope planner, exact whole-data-tree content hashes and confirmation fields before deletion. Symlinks, hardlinks, extra entries and stale snapshots are rejected. Results distinguish partial failure and preservation/metadata verification failure; receipts are not backups or recovery permissions. This private test harness does not claim protection against a malicious concurrent process under the same OS user and must never be adapted to real sources by swapping a path.

## Native contract test helper

`scripts/native_codex_contract.py` is an explicit developer test entry point, never imported or bundled by the app. It requires a trusted official test executable with exact version 0.162.1, creates its own canonical temporary data roots, reconstructs the child environment from a whitelist and forces file credential storage and a generated sqlite_home. SQL fixture setup/inspection only touches this generated database. The helper compares a copied generated rollout corpus through the production Rust planner with the generated native spawn graph; that copy is not an atomic live-store snapshot. Native scope assessment always reports executionEnabled=false, even when the ID sets match. Real inventory scan and the unconditional production execution lock are unchanged.
