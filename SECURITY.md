# Security

AgentBroom starts with metadata-only local inventory. Real native deletion is available only through a backend-owned plan and an explicit desktop confirmation; there is no automatic selection, scheduled deletion, arbitrary root/executable IPC or browser write endpoint. Missing metadata does not prove data disposable.

## Native owner

The regular desktop discovers the configured source internally. A private generated-store owner remains separate and is absent from the regular dependency graph. Observation types and native scope equality alone never authorize mutation. Supported exact runtimes and migration checksums are verified; existing incompatible databases are not upgraded. Preview reads native SQLite state read-only, validates pins, references, paths, identities and budgets, and hashes the selected files. Execution revalidates short-lived opaque plans, Keep inputs, contents, runtime and scope. A five-minute recent-write protection is additional caution, not proof that older conversations are inactive. Official lifecycle/writer/reference protection remains authoritative.

Only final confirmation persists execution intent and starts a source-bound official stdio process, with reconstructed environment, process-local ephemeral credential storage, offline model provider, isolated non-source runtime state, output/deadline limits and no daemon reuse. It uses `thread/delete`; AgentBroom does not manually unlink real rollouts or write native SQL. Native deletion may remove associated native metadata and update shared indexes. Unknown, partial and verification failures are never success and never trigger automatic retry. Receipts contain IDs, relative paths and verification facts, not transcripts, under private `~/.agentbroom/cleanup-receipts/`.

Selected file content and native/observed sets must still match. Retained static files use complete kernel identity/length/mtime/ctime checks; recently changing retained files also use content-prefix hashes to distinguish appends from rewrites. Unselected native records/edges are checked. New concurrent files and verified appends are reported. This does not establish an atomic live-store snapshot, full auxiliary-data accounting, reclaimed space or recovery. Application instances serialize operations; graceful exit waits for the worker and closes owned processes. Forced OS termination can leave an unknown receipt that must be investigated.

## Inspection and input handling

Session metadata, including bounded Zstandard headers, title index and pin state are untrusted data. They never become instructions. Paths are checked, links/special files rejected, and input/output/decoder/graph budgets bounded. Bodies are not displayed or exported; selected content hashing is for freshness, not interpretation. Native state/config checks do not publish credentials. There is no AgentBroom cloud service, telemetry or model call. Local-owner controls do not isolate against a malicious process with the same OS privileges.

The loopback development gateway only accepts same-origin read requests through its fixed own-project scanner. Native cleanup uses local IPC, not HTTP. Automated destructive tests must use newly generated stores and explicitly selected official test binaries; real conversations are never debugging fixtures. Internal designs, reviews and logs in local `docs/` are not distributed. Do not put private metadata or credentials into public issues. Prefer private vulnerability reporting when enabled, otherwise contact the maintainer through GitHub for a private channel.
